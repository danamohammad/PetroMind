RESEARCH EDITION · REVIEW RECORD · 25 OCTOBER 2026

What changed, and what was checked.

PetroMind is a rebuilt browser workbench based on the supplied PetroMind AI prototype, composition and operating conditions. The original archive is preserved separately. This record distinguishes software verification from experimental validation.

No laboratory validation is claimed. Agreement between two equation-of-state implementations does not prove agreement with a real fluid. No measured PVT dataset accompanied this release. Heavy-cut properties remain assumptions and require characterization before engineering use.

Findings in the supplied version

  • Heavy-fluid laboratory comparison was disabled. In the integrated entrypoint, the lab branch treated pseudocomponents like a missing upload. The replacement uses the same compositional model for light and heavy fluids and reports errors against entered measurements.
  • Several advanced functions did not support the supplied heavy fluid. Stability, tuning and model-comparison branches were disabled for pseudocomponents. This release does not present unavailable features as working predictions.
  • Startup was not reproducible from the README. It named a missing entrypoint; dependencies omitted scientific packages used by the code. The archive also contained a Windows virtual environment. The browser release provides pinned scientific packages and a portable static deployment.
  • Publication needed a clean boundary. The archive contained a secrets configuration, environment files and IDE state. These are excluded from the public repository and website. Secret values were not needed for the rebuild.
  • Heavy-end assumptions were easy to overlook. The supplied critical properties and acentric factors are retained as editable, explicitly uncalibrated inputs. Verify that the named plus fractions represent distinct, non-overlapping cuts.

Corrections and improvements

  • Separate fluid, laboratory, production, saved-project and methods workflows; responsive layout and interactive charts.
  • Manual data entry plus CSV/XLSX import; CSV result exports, PNG chart downloads, printable PVT reports and complete project JSON backups.
  • Explicit fraction normalization, duplicate/invalid input rejection, SI-to-field unit conversions and named reference conditions.
  • Component-balance and fugacity-residual checks. Failed calculations remain gaps; unavailable quantities are distinct from valid zero.
  • Two-stage surface separation with material balances, reservoir-liquid Bo/Rs basis and gas reference-state checks.
  • Vapor/liquid branch identity is retained explicitly; dense vapor is not silently relabeled as a second liquid.
  • Editing inputs marks old results stale and disables their export until recalculation.
  • Production dates use actual elapsed days. Missing water measurements are distinct from zero. Exponential forecasts are labeled as simple baselines and require declining rates.
  • Chart sharing to third-party services is disabled. Calculations and project data stay in the visitor's browser.

Independent numerical comparison

The new Thermo 0.6.1 Peng–Robinson implementation was compared with the original extracted ThermoPack 2.2.3 calculation worker using identical compositions, constants, interactions and separator conditions. All four cases passed a tolerance of max(10−6 absolute, 10−6 relative). The largest nonzero relative difference in the recorded values was below 5 × 10−8.

Automated checks cover invalid fractions, duplicate components, mass balance, gas-only states, zero-valued measurements, data parsing, production fits and CSV safety. Source tests and the complete comparison data are available in the public repository.

Scope of the implemented model

PR, PR78 and SRK cubic vapor–liquid equilibrium; one liquid and one gas phase; two surface separation stages; pressure sweeps; independent temperature–pressure bubble/dew roots; measured-versus-predicted errors; and a simple exponential production baseline. Saturation roots are not a complete continuation phase envelope. Critical points, quality contours, uncertainty bands, automatic EOS tuning, brine/solids, wax and asphaltenes are not implemented. No AI-trained prediction model is claimed.

Constant heat-capacity placeholders support phase construction only: this release reports no enthalpy, entropy or thermal-process results. Pure-component constants and default PR interactions came from ThermoPack; SRK may need separately fitted interactions.

Storage, operation and maintenance

The first calculation downloads Pyodide and scientific Python packages, so allow extra loading time and keep an internet connection. Files are parsed in the browser; no analysis server receives your measurements. Hosting and package providers still receive ordinary web requests. Saved projects use local browser storage and do not synchronize between devices. Export project JSON for durable backups.

Cloudflare serves the static application at petromind.dana-edu.pp.ua. Source changes require testing and a new Wrangler deployment; pushing to GitHub alone does not update the website.
